# 07 · 测试与质量门槛

## 1. 测试策略

2026-09-24 补充：草稿生命周期（确认离开删除本机草稿、恢复时全部字段可见、退出成功才清理、换账号清理他人草稿）、无 Navigation API 的后退保护、任务在别处删除后页面与草稿保留、失效任务链接不整页 404，均由 `tests/e2e/draft-lifecycle-and-deleted-tasks.spec.ts` 覆盖，并在原实现上确认失败。看板筛选集合跨页变化、生产页面与 API 共用读取额度、认证邮件响应后投递（拒收与停滞 SMTP 替身）、连接池饱和 P2028 → 503、上传超时/中断/依赖故障分类，分别由真实 PostgreSQL 集成测试覆盖；过期会话与验证记录清理由恢复演练的一次性数据库验证。

2026-09-21 补充：任务创建收起与退出登录必须先确认草稿；拒绝登出时不得发送 sign-out。真实看板验收默认优先级、非筛选 URL 变化、协作计数与实际配额恢复。数据库回滚在独立夹具范围内注入 ActivityLog/IdempotencyRecord 真实 INSERT 失败，先由触发器确认 Task/Project 已修改，再断言事务后的多表快照不变，finally 移除探针。HTTP 限流验证真实 60 秒窗口与 Retry-After 恢复；due/priority 排序同样执行 p95≤300ms 断言。传输名额需覆盖正常、错误、取消、超时及临时空间不足。

认证超限回归必须使用合法 JSON 并调用真实 handler 断言 413；“非法 JSON 自然抛错”不能证明限流。SMTP 用持续慢速推进的协议替身验证 20 秒后真实连接关闭；下载覆盖响应头及响应体停滞、截断、取消与正常字节一致。

工作台错误恢复通过测试服务器进程预加载模块，在真实 pg 查询上仅对本轮指定用户注入失败；生产源码没有测试路由、请求参数或开关。浏览器断言真实错误边界出现、点击 retry 发出新 RSC 请求、故障解除后恢复内容。

测试清理在所有关联删除之前验证本轮用户所有权清单，拒绝历史夹具；前后内容指纹仍为最终门禁。历史事故与无法恢复的证据缺口见 [当前交付边界](CURRENT-STATUS.md)。验证记录由 scripts/verify-remediation.mjs 捕获真实子进程退出码、完整日志散列和源码摘要；遇失败停止，不用后续命令退出码覆盖失败。

单元测试覆盖日期、权限决策、排序和输入规则；集成测试用真实 PostgreSQL 验证事务/并发/权限；契约测试验证自有API；E2E覆盖主要用户流程。不要用全部mock的成功响应代替后端测试，也不要为纯样式和复制实现逻辑的代码堆测试。

外部邮件/存储/AI在多数测试中使用受控替身，但M1邮件、M5存储和M7 AI各要实际联调。CI使用本地Mailpit/S3 兼容存储（SeaweedFS）及测试数据库，不能连接生产账户。计划文件的静态校验不等于本章应用测试。

AC-01对应AUTH；AC-02对应PROJECT/TASK；AC-03对应INVITE；AC-04对应PERM；AC-05对应TASK-02/CACHE；AC-06对应BOARD；AC-07对应DATE；AC-08对应COMMENT/SUBTASK/FILE；AC-09对应MEMBER；AC-10对应TASK-05；AC-11对应A11Y/RESP；AC-12对应DEPLOY和发布报告。

每个backlog任务记录至少一条实际evidence。文档矩阵覆盖要求不意味着所有条目都必须各写独立测试文件；可按行为合并，但不能漏掉风险。

## 4. 性能目标及测量方法

以下是待验证预算，不是已达成结果：

- 面向最终真实流量：Core Web Vitals 第75百分位 LCP≤2.5s、INP≤200ms、CLS≤0.1。没有足够真实访问时明确只有实验室数据，不能声称达到真实用户分位。
- 初次可交互工作台：在记录的Chrome版本、1440px、4倍CPU降速、明确网络配置下测试；使用正式构建，连续5次，保存中位数及范围。
- 关键业务JSON读取p95≤300ms、普通写入p95≤500ms：在本地/同区域staging、10并发、每项目1000任务的明确数据集上测量，排除AI/邮件/上传，记录硬件、样本数和错误率。
- 初始看板每列最多50张；TaskSummary不传description；首个看板JSON目标≤250KiB未压缩。实测超预算先分析字段/查询，不删除必要可访问性信息。
- 拖拽与筛选不能造成明显长时间主线程阻塞；用Performance trace定位，不能只依据主观“很丝滑”。

不把Lighthouse的TBT写成INP。只有一个用户时不虚构p95在线指标。图表库、Markdown编辑器和上传处理按需要懒加载；V1无需分析图表库。

## 5. 可访问性与视觉门槛

普通文字4.5:1，大字号与关键非文字控件3:1；状态同时有文字/图标；焦点明显且不被面板遮挡。Dialog正确标题、aria描述、初始焦点与关闭后恢复焦点；toast不能是唯一错误反馈。

自动axe扫描无critical/serious问题作为最低门槛，再人工走主流程。按钮触控区、200%缩放、长中文/URL、减少动画偏好要检查。截图基于稳定fixtures；截图差异须人工确认原因，不能批量更新baseline让测试变绿。

## 6. 安全与数据检查

所有角色、归档态、软删除态、关联资源归属在API层有测试。没有任何文件桶公开读写；下载URL签发前重新鉴权。Markdown不执行HTML/脚本，不读取外部图片；评论始终纯文本。查日志与构建产物不得含凭证/令牌/私有正文。

依赖扫描的问题按实际可达性和修复方案处理，有明确可利用的高危漏洞未处理时不能标记发布完成。不要为了减少告警停用扫描或关闭TLS校验。

## 7. CI与发布验收

每PR：lint → typecheck → unit → contract → integration → production build → E2E smoke。测试数据库隔离，Mailpit/S3 兼容存储服务按需要启动。全套E2E在合并前或发布候选运行；不能以“本地通过”替代CI结果。

关键端到端套件固定3条：单用户完整任务生命周期；双用户邀请协作和移除；私有附件上传下载失败恢复。发布前另跑三种视口、键盘、性能与备份恢复。

不设会诱导无意义测试的覆盖率百分比；按关键业务规则覆盖验收。允许记录尚未验证的外部条件，但对应任务不得标为done。可按需生成**信息性**覆盖率报告（工具/套件/排除范围需注明），不作为门禁。

生产 requireTLS 分支由真实回归覆盖：tests/integration/read-quota-and-smtp-security.test.ts 以生产配置连接无 STARTTLS 的真实 SMTP 协议替身，断言 AUTH 未发送。性能参数（页大小、池上限、预算）均为已审阅的固定值，采样环境与样本量记录在当次运行产物；不因环境差异临时放宽。

### 上线前回归要求

SMTP 在 staging/production 拒绝无 STARTTLS 服务且不发送 AUTH；GET/HEAD 共用生产读取额度；附件后台 503 与重试保留选中文件和上传；IME Enter/Escape 不提交或销毁草稿；认证失败 teardown 精确清理重置记录且全量集成前后两库内容指纹一致。代理以合成查询令牌、路径令牌和 Referer 分别验证成功/失败日志无秘密。S3 非当前版本保留 30 天，覆盖数据库 7 天备份窗口；不自动过期当前文件。
