## 额外优化与边界

- **看板统计合批：** 三列先读取页面，再一次汇总本页任务的协作计数；保留原有 RepeatableRead 一致快照、游标和权限检查。真实数据库验证三列计数隔离、删除评论排除及状态筛选。
- **传输资源限制：** 单 Node 进程最多同时上传 4 个、下载 8 个，同一用户各最多 2 个。上传准入要求临时目录至少有 104 MiB 可用空间（64 MiB 余量加 4 个最大文件）。并发不足返回 429，空间不足或无法读取返回 503。完成、失败、取消、超时均释放名额；既有跨进程 PostgreSQL 上传配额仍保留。
- **限制适用范围：** 新的总并发边界是每进程边界，不是跨副本集群配额，也不保证整机不会被其他进程填满。新增水位检查已在 Windows 实际上传及 Linux Node 24 只读容器的 128 MiB 临时盘验证。服务器容量调优、崩溃残留策略和混合流量测量待真实部署；没有擅自删除其他进程临时文件。
- **接口一致性：** comments GET 使用统一中文校验和字段错误；task DELETE 的版本参数采用与子资源一致的正十进制安全整数规则，并拒绝重复版本参数。同步 docs/05，OpenAPI 的正整数结构未改变。
- **真实故障回滚：** 对精确测试夹具注入 ActivityLog / IdempotencyRecord 写入失败，确认 Project/Task 已修改后再失败，并验证计数、编号、版本、事件和幂等记录整体回滚。测试移除专属触发器后验证恢复成功，没有模拟事务结果。
- **性能与限流覆盖：** 为三种任务排序补 p95≤300ms 断言；新增真实 HTTP 写限流到期恢复，实际等待 Retry-After；下载测试核对正常、截断、取消、建连超时和 120 秒总超时均回收资源。
- **兼容性：** 未保存离开保护补 beforeunload 的 returnValue 兼容路径。没有改变数据模型、引入新服务或扩大 M7 范围。

Node 文件系统接口依据：[Node 24 statfs 官方文档](https://nodejs.org/docs/latest-v24.x/api/fs.html#fspromisesstatfspath-options)。原报告中的误报、已有明确规格的设计和缺少现场证据的推测，继续采用原报告逐项处置，不为制造“全部改过”的表象破坏权限、游标、一致快照、幂等或数据库历史。
