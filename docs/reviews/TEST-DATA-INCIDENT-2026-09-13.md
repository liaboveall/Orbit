## 已实施的防误删措施

- 测试套件开始时生成独立临时清单，记录开始时间和既有用户 ID 的 SHA-256；不写入邮箱、密码、会话或令牌。
- `cleanupTestEmails` 在同一事务中锁定精确邮箱对应用户，并在执行任何关联 DELETE 前核对清单；拒绝历史用户、早于本轮的用户和缺失清单。
- 集成认证清理助手也在删除令牌和账户前执行相同核对；最终删除使用读取到的精确 ID 集合。
- 本轮 E2E 回归直接请求清理一个基线用户，断言在删除前拒绝；空库 CI 验证缺失清单时拒绝。单测覆盖历史 ID、旧时间戳、本轮 ID 与清单缺失。
- 套件结束再次比较开发库与测试库完整内容指纹；验证失败必须使命令失败。临时清单结束后移除。

这能约束正式清理助手，不能约束绕过助手的任意手写 SQL。因此调试也必须使用本轮精确夹具集合和正式门禁；禁用按广泛前缀/模糊条件删除既有用户及其认证关联记录的做法。后续生产备份仍按 M6 的独立验收要求完成。
